# 运行条件与独立审核

PMSpec 不依赖 OpenSpec、superpowers 或 proto-gen。套件自包含不等于宿主无需能力：

| 阶段 | 宿主能力 |
|---|---|
| explore | 对话；有资料时具备获授权的读取能力 |
| propose | 对话、读取与写入工作区 |
| apply | 文件读写、浏览器实测、独立子 Agent |
| review | 读取与整理需求文件，按用户明确说明更新状态；`--check` 只读验证引用 |

HTML 打开无需 Node、Python、服务器或网络。内置资产嵌入脚本使用 Node.js 内置模块，无 npm 依赖；无 Node 可手工内嵌三份资产，不自动安装。

## 初始化与宿主适配

使用同套件 pmspec-init 准备五个技能及命名审核 Agent；首次尚未安装时可让 Agent 从仓库 README 的通用初始化文本开始。规则和资产始终由本套件提供，不依赖外部技能。

```text
Claude Code                          Codex
.claude/skills/pmspec-*/              .agents/skills/pmspec-*/
.claude/agents/prototype-review.md    .codex/agents/prototype-review.toml
/pmspec-apply 需求名                  $pmspec-apply 需求名
```

Apply 的 assets/、references/、scripts/、agents/ 必须整体安装。不要覆盖同名不同内容，保留项目特化规则。新建 Agent 目录或宿主尚未发现时可能需要重启，磁盘文件不等于已加载。

Claude Code Agent 用 Read/Glob/Grep 白名单限制写入；Codex Agent 继承父会话权限，仅通过开发者指令约束只读，不能当作独立只读沙箱。两种宿主定义都读取本技能相同的审核清单，不维护两份审核规则。

初始化必须验证技能发现、以 `--check` 只读引用 Review，以及命名 prototype-review 独立规则读取冒烟。引用检查不提供需求名、不查找或整理产品资产、不读写需求状态；冒烟不是原型审核，不能据此标原型可交付。本节仅说明准备方式，Apply 自身仍需检查实际能力；不在运行中静默调用 init 改配置。

## 固定预览与验证入口

HTML 仍自包含、双击可用；自动验证的 HTTP 入口不成为交付依赖。优先复用当前宿主已验证方式：宿主禁止 file 协议时直接走 loopback HTTP，不再每轮重试；双击/离线未实测如实列 Not run。

- `node "<APPLY_DIR>/scripts/preview.mjs" "<HTML>"`：仅暴露该 HTML 字节快照，绑定 127.0.0.1、自动分配空闲端口，输出 URL、SHA256、PID；不开放目录。修订后重启取得新版本，不以旧服务验证新文件。前台 Ctrl-C 停止；自动宿主须持有本次服务句柄，在取齐结果后关闭，不留服务等下一轮、不结束任务等待后台完成。平台若限制启动方式，遵守平台约束。
- `node "<APPLY_DIR>/scripts/inspect-html.mjs" "<HTML>" "<section ID 或函数名>"`：只读输出命中附近行号，省略内嵌 base64 并保留换行；原字节哈希不变。无定位参数输出全文精简视图。它不是交付 HTML，不可写回、不代替图片视觉核对或完整差异核验。
- [browser-checks.js](../scripts/browser-checks.js)：无依赖的宿主浏览器函数表达式，传入现有 `page` 和 `{url, sha256, cases, reset, capture}`。复制/拼接此表达式后交宿主执行，不在浏览器服务器中 require/import 模块。具体适配、用例与结果导出见 [验证脚手架](verification-harness.md)。未实测宿主能力不宣称可用。

运行索引仅放需求目录外临时区，写当前 HTML/提案、设计版本与批准来源、section/函数定位、可复用用例、已验证宿主入口、当前版本证据及未测项。每轮先核对索引所指文件/版本和新增评论；索引只导航，不替代事实源，不免除平台要求的评论追读。按相关 section/函数定位读取，跳过 base64；共享脚本、样式与素材依赖仍须核对。

## 审核调用契约

主 Agent 实测后，按 [项目设计依据与审核交接](design-context.md) 的表格提供输入；交接区分首次/无基线全量与有可靠基线的增量模式，按 [增量验证与交审](incremental-review.md) 提供完整差异、影响范围和证据链。生成和审核读取同一设计入口、所涉通用/组件/模式/品牌文件、来源版本、采用状态及批准范围。不增加强制配置文件，无项目依据时明确使用内置默认主题。

### 显式调用与等待（强制卡点）

先确认命名的 `prototype-review` 已被当前宿主发现且注册定义与本次套件版本一致，再调用。若旧注册指令仍要求旧结论或与当前清单冲突，报告待更新/重启验证；读取新版磁盘定义不能覆盖旧的高优先级注册指令。Claude Code 的 Agent 工具调用示例（先将占位说明替换为本次真实输入）：

```json
{
  "subagent_type": "prototype-review",
  "description": "独立审核当前原型与证据",
  "prompt": "按本次 apply 技能路径下的共享清单只读审核。交审输入：目标 HTML 与版本、proposal 与批准来源、设计依据及适用范围、复用映射、apply 技能绝对路径、当前浏览器证据与 Not run、上一轮报告及本轮修改（首审写无）；增量时附可核验基线、完整差异、影响范围与逐项证据链，无可靠基线退全量。返回完整评分报告，末行按清单固定格式。",
  "run_in_background": false
}
```

Codex 使用当前宿主提供的独立子 Agent 调用机制，显式选择已注册的 `prototype-review`，传入相同输入并等待完整返回；不照搬 Claude 的工具名、参数或伪造通用 API。找不到当前版本的命名调用能力时报告阻塞，不把 TOML 文件存在当作可调用。

- 必须在当前任务内取得完整报告后再继续。宿主强制异步时，用该宿主提供的等待/取回机制收齐结果，不启动后就交付，也不把部分输出当最终结论。
- Agent 未加载、无响应、规则无法读取或结果格式错误：报告“审核未完成”及原因，保留草稿；不由 PM 编分数或结论、不绕过命名限制、不换通用 Agent 或另一个宿主 CLI 代审。
- 收到报告后，对照 [唯一评分表](review-checklist.md) 校验全部检查项、六维小计、总分、硬性条件及固定末行，不能只搜索“审核通过”四字。可用 `node "<APPLY_DIR>/scripts/check-review.mjs" "<报告文件>"` 做格式与算分检查；退出 0 为报告通过，1 为有效不通过，2 为格式/算分无效。脚本不替代证据真实性与问题语义核对；无 Node 时手工执行同等核对，不安装依赖。
- 有效不通过：PM 集中修订必改项及导致不通过的偏差，复测受影响项、更新文件版本与证据，再交原命名审核子 Agent 复审。用宿主支持的续接方式保留上下文；不能续接时再次调用同一命名 Agent，完整传入上一轮报告和修改，说明是新上下文复审，不声称已续接。
- 只有独立审核者对当前版本给出有效通过，才进入待人工验收。需要产品裁决或无法补齐必需证据时说明阻塞，不为通过而擅改需求。

没有独立命名子 Agent 或浏览器实测能力时，只能保留未完成验证的草稿。人工代看、PM 自查或规则读取冒烟都不能包装成原型审核。

## 证据生命周期

按[交付清理约定](delivery.md)把截图、脚本、实测结果、交审说明与审核报告放在需求目录外的运行临时区；命名审核者读取该位置的当前版本证据，仍执行完整审核与复审。审核未完成不提前销毁证据；正式交付前先把版本、结论、Not run 与必要证据写入宿主持久任务记录，再按已授权清单清理。需求目录最终默认只留 proposal 和统一原型 HTML，不用 archive/ 替代清理。

## 可验证的完成含义

- 静态检查通过 ≠ 浏览器实测通过。
- 浏览器实测通过 ≠ 独立审核通过。
- 独立审核通过 ≠ 用户验收通过。
- 本机安装文件存在 ≠ 新会话技能加载成功。

每项结论注明实际做了什么，未做写 Not run 及原因。不为跑通流程擅自安装浏览器服务、修改 settings.json、申请扩大权限或创建平台 Agent。
