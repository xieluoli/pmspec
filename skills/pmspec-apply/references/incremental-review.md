# 增量验证与交审

减少重复定位与无关重跑，不降低审核门槛，不设固定断言数或承诺耗时。首次制作、无可靠基线或需求/设计依据变化时全量；纯文案也不默认免除独立审核。

## 可靠基线

须同时具备：可读的上一轮 HTML 原字节及 SHA256、对应有效独立审核报告及其哈希、浏览器原始证据及其哈希、当时 proposal/设计依据的版本与批准范围。当前审核规则有变化时，另核对变化对既有证据的适用性，不继承已失效判断。

交审列明当前 HTML SHA256、提案/设计依据版本、基线各文件位置与哈希、基线到当前的完整差异及影响范围。未提交文件以字节哈希标识，不用 HEAD 代替工作区版本。包括共享 CSS/脚本、素材、旁注、索引与跨图联动；不能只给修改说明、片段 diff、时间戳或旧评分。大段 base64 可用精简只读视图定位，但原文件和完整差异须可核验，素材变化另外列哈希和视觉证据。

审核者独立核对差异是否完整、影响面是否充分；基线不可读、版本不符、证据缺失、依据已变或影响面不明则退全量。不得为快而假定未变部分有效。

## 按影响范围复测

| 变更 | 最少重新验证范围 |
|---|---|
| 局部文案/旁注/按钮 | 当前画面、溢出/遮挡、对应行为/状态、旁注与提案一致性；仍走独立审核 |
| 单页/弹窗/新图示 | 该图全部适用状态、入口/返回、索引、相邻上下文；新图示不借基线免测 |
| 共用状态机/持久状态/权限 | 全部消费者、状态切换、失败恢复、跨图同步及权限边界 |
| 共用样式/外壳/主题 | 所有受影响图示及组件变体、关键视口、最终生效样式 |
| 需求/设计批准范围变化、无可靠基线 | 全量验证和审核 |

每轮保留关键流程冒烟，包括索引可达、主路径、控制台/外部依赖与整页溢出；项目明确关键路径后复用其用例，不把通用脚本检查当成完整产品冒烟。每条用例独立重置，不能依赖上一条安装/保存后的残留状态。用例只点击当前可见且应可交互控件；禁用状态用属性断言，不强点等待超时。焦点验证不得为了避免滚动而绕过待验证的真实点击路径；只测键盘时使用键盘。

## 完整评分与证据链

仍执行 [唯一审核清单](review-checklist.md) 的全部 15 项及硬性条件，不能沿用旧分数或删项改分母。每项证据标明：

- **当前实测**：当前哈希、定位、步骤/结果及样式/截图位置。
- **基线继承**：基线哈希与原始证据定位、完整差异核验结果、共享依赖未受影响的依据，以及本轮冒烟覆盖。由审核者重新判断，不等于重新运行未变部分。
- **未验证**：缺口与 Not run，暂计 0；按清单不能判通过。

上一轮必改与待确认项逐条复核，集中修复后复测受影响项，续接原命名审核者或完整传入前轮上下文。不能续接时如实说明新上下文复审。报告完整取回并验证后才交用户；审核通过不等于人工验收。

## 精简运行索引

可在需求目录外临时区用一份 Markdown 维护，无强制配置格式：当前 HTML/提案与哈希、批准记录、设计入口/来源版本、section/函数定位、基线与完整差异、影响范围、可复用验证入口/用例、当前结果/未测项、前轮审核报告。每轮更新失效项，不复制整套规范，不把聊天摘要当批准原文。

过程证据按 [交付清理约定](delivery.md) 持久留痕后清理。已清理的基线无法取回时退全量，不为以后提速私留额外交付；基线可从获授权的历史提交或持久附件恢复，仍需核对哈希。
