# 功能概览写作规范

读者是产品、测试与研发。描述最终产品，不描述它在聊天中如何演变。

## 写法

- 面板名固定“功能概览”。按画面从上到下，一个可感知元素一条，用“**元素名**：”起头。
- 交代展示内容及数据来源/行为；数据来源用“用户输入”“配置”“示例数据”等普通语言。
- 按钮说明点击结果，字段说明关键默认值、限制与校验，状态说明触发条件和变化。
- 关键交互、失败与恢复路径独立描述，不藏在大段末尾。
- 条件改变行为时分别说明每个分支；轻量子 Tab 的对应状态应可从旁注明确找到，或切换时同步旁注。

示例：

- **名称输入框**：由用户输入，去除首尾空格后须为 1–20 个字符；未填写时不允许提交。
- **保存按钮**：点击后校验名称；通过后模拟保存并返回列表，展示新条目。
- **保存失败**：展示失败提示，保留已输入内容，允许重试。

以上数值只是示例，不可照搬为其他产品决策。

## 去噪而不漏规则

- 不写类名、组件/路由名、颜色数值、像素、圆角、组件出处、聊天修改史或长篇辩护。
- UI 文案说明用户需要判断或操作什么，不讲后台实现；同一结论一屏不重复。
- 系统级外壳说明“跟随目标平台”，不把 macOS 外壳写成跨平台产品需求。
- 新页面完整描述；既有页面改版只描述本次新增或变化。通用外壳首屏说明，后续不重复；有变化才写差异。
- 内容级重复可引用明确编号，如“表单结构同 02，差异如下”；不用“同上”造成跨文件歧义。
- 已批准的待决项删除；模拟行为明确标记。旁注与 proposal、交互结果冲突时不能自行选一份，先核对批准依据。
- 复杂层级或状态关系配 ASCII 图；不要以图替代关键规则文字。

## 同步

原型修改后回扫旁注的按钮、字段、状态与流程。不默认维护独立 PRD 副本。proposal 保存需求范围和关键规则，旁注展开页面细节；同一规则有明确权威位置，必要时引用，不产生相互矛盾的多份口径。
