# 流程画板与母版

## 从用户目标排版

绘制前列一张工作路径表，至少标明「用户起点与前置条件 → 实际操作 → 到达页面或反馈 → 完成或恢复」。给新页面、弹窗、抽屉、关键反馈及分支一个明确位置。用实际先后组织全貌，分支紧跟触发步骤；跨流程共用的界面引用已有锚点。用现有设计还原必要上下文，既有且未改动的界面只在用户需要经过时出现。

按页面或步骤聚合同页状态。组内默认顺序为常态（有数据）、空数据、异常、加载；权限、禁用、提交等状态按触发环节邻接，可按真实流程调整。仅覆盖适用且属于本次变更或影响路径的状态。触发条件、可操作项、数据保留、下一步或恢复方式有实质差异时，展示可辨别的状态与对应行为。若多个原因确实表现为同一画面和操作，可用合并标题展示一次，旁注明确每种触发条件，体验仍可复现各场景。仅改局部条件且无需额外图解时，在原组件旁注和体验中覆盖。

## 全貌与连续体验

- 默认展示全貌。每个流程分区有标题和稳定锚点，使用留白或分隔线；多图时用一个可收起的索引定位具体画板。主要页面和有差异的状态始终可见。窄屏可单列；宽屏横排时阅读顺序仍与索引一致。
- 每幅图左上标明页面与状态，右上统一放「进入体验」。每个入口用对应的初始页面、数据、权限和叠加态打开体验，可直接返回全貌原位置。全貌是独立快照，交互由体验承接；页面索引属于评审工具。
- 体验中的用户点击走真实产品路径，状态和数据沿路径传递。每条主流程能到完成或明确结果，适用时支持返回、关闭、取消、重试、无权限反馈和恢复。入口、完成与失败均从可见控件验证，评审场景切换只用于复现前置条件。
- 场景开关、重置、模拟说明放在产品画布之外。切换场景时给定完整初值；重置取消待执行的模拟、恢复初始历史和数据。窗口或设备按实际产品及项目设计选择，移动端保留必要系统栏、边距和内容滚动，窄视口等比适配或重排评审层。叠加层应限制在所属产品画布内。

## 单文件母版

- 共享同一套设计 token、设备壳、导航、页面渲染器和重复业务组件。用 CSS、原生模板或渲染函数按数据与变体实例化。项目设计优先，通用样板仅供无项目依据时起步。
- 用一份场景定义驱动索引、全貌快照及「进入体验」初值。关联组件通过稳定规则键读取同一份旁注；状态差异以参数或规则覆盖表达。渲染快照使用新的场景实例，不借用或修改体验数据、历史与计时器。
- 每个实例的 DOM ID、事件和叠加层各自限定作用域。共享母版改动后同时复测全貌与体验中的消费者。必要资源直接内嵌在唯一 HTML，用户输入通过文本节点或安全 DOM API 渲染。
