# PMSpec · Review

全程中文。整理最终需求资产，让 proposal、原型画面和功能旁注保持同一口径。需求澄清与查缺补漏在 Explore、Apply 完成；本阶段不增加需求逻辑审查、原型评分或独立报告。

## 只读引用检查

当 `$ARGUMENTS` 为 `--check`，或用户明确要求仅验证技能引用时，只返回技能名称、三项职责及支持的需求状态，并说明“仅验证技能引用，未整理资产或变更状态”。不查找产品需求，不创建、修改或删除文件，随后结束。Init 用此模式验证引用，不能以正常整理模式代替。

## 输入与范围

1. 确认产品 workspace 和需求名；名称只允许小写英文、数字与单个连字符分隔，不接受路径、斜杠或 `..`。缺少名称、多个候选或目录不明时先问，不猜。沿用项目指定的需求根目录，无约定时使用 `pmspec/changes/<需求名>/`。
2. 正常整理时先盘点当前需求目录的文件，区分正式资产、获准附件及其他文件，再读取 proposal、已有原型及本次获批准的需求来源；内部记录各项处理情况，不新增清单文件。核对 Git 与未提交改动，保护他人内容；归属或用途不明的文件先保留并询问，不默认处理。缺 proposal 时报告缺失，不创建空需求；原型缺失时可整理 proposal，但明确“原型对齐未检查”，不自行生成原型。
3. 用户调用本技能整理需求，授权在该需求已有 proposal 和原型内合并重复、清除过程叙述及同步有明确依据的内容；不授权替用户决定范围、业务规则或状态，不授权删除文件。用户仅要求变更状态时只处理状态字段，不顺带整理正文或原型。

## 整理与内容对齐

- **最终口径**：清除“根据本轮讨论”“用户后来要求”、已废弃方案和补丁式变更记录，将仍有效的规则合并到对应位置。保留有依据的真实产品现状与本次差异，不把所有“由 A 改为 B”一律删除，也不为简洁丢失权限、状态、限制和验收要求。
- **逐项对齐**：比较 proposal 的功能与关键规则、对应原型画面及旁注，定位遗漏、矛盾和过期内容。仅在用户已确认的最终口径足以确定修改内容时同步；不能把某个文件、时间较新的版本或聊天旧稿自动当作权威。涉及产品取舍或依据不足时，列明两侧位置、差异及影响，先询问用户，继续处理不依赖该决定的整理项。
- **验证边界**：不以文字核对代替浏览器实测或独立原型审核。修改 HTML 后按 Apply 的[增量验证与交审](../pmspec-apply/references/incremental-review.md)更新版本与验证；未完成时如实标待验证，旧审核结论不适用于新版本。需要补充产品决策、页面或交互时建议在 Explore 或 Apply 处理，不自动调用下一阶段。
- **文件组织**：沿用[两文件交付与清理约定](../pmspec-apply/references/delivery.md)，只保留现有获准的正式产物；发现多余文件先盘点，取得具体删除授权并保留必要证据后再清理。项目级设计资产不在清理范围，不另建报告、状态文件或需求内归档目录。

## 需求元数据（唯一维护约定）

- `proposal.md` 文件最开头使用 YAML Front Matter，固定字段为 `name / version / status`，位于正文标题之前；正文不重复维护这些元数据。例如：

  ```yaml
  ---
  name: simplify-project-creation
  version: "1.14.1"
  status: 未评审
  ---
  ```

- `name` 与需求目录名一致；`version` 是该需求对应的**产品发布版本**，用带引号的字符串保留项目原有版本格式。名称和版本示例不是默认值；从用户明确说明或项目已确认的该需求发布安排取值，不从套件版本、Git 分支或文件修改次数推断，不随文档整理自动递增。版本未知或依据冲突先询问，修订保留已确认版本。
- `status` 取值仅为 `未评审 / 待发布 / 已发布`。新建需求默认未评审；用户已明确当前状态时按其说明填写。待发布表示产品功能待上线，已发布表示产品功能已上线；这不是文档发布状态。其他文件如需说明元数据，引用 proposal，不维护第二份值。
- 存量需求为旧格式、缺字段或元数据冲突时，先核对已确认信息，缺失或冲突部分询问，不批量迁移或猜测；迁移只改变存放形式，保留原有状态、版本和业务正文，不遗留第二份状态行。仅更新状态时只改既有状态值，保留 name、version 和正文，不顺带迁移旧格式。
- **已有需求仅在用户明确说明后变更状态**，指令须能确定需求和目标状态；含糊表述先问。整理完成、提案获批、原型审核通过、提交或合入均不触发状态变更，不要求按固定顺序迁移。
- 已发布需求发生修订时保留原状态，仅询问用户是否需要调整；没有答复就保持不变，不自动退回未评审。Propose、Apply 修订同样遵守此规则。

## 交付

正常整理结束时对照盘点逐项复核，区分已整理、无需修改、待确认和未检查，避免遗漏资产；清单内部使用，对话仅说明实际改动和未完成项。规则或入口有修改时，核对其在 proposal、原型画面、旁注及已知直接关联索引中的所有出现位置与受影响引用；范围限当前需求及直接引用，不扩大为全项目清理，需求目录外未获修改授权的索引仅提示需同步的位置。

在对话中简述需求与原型对齐结果、当前状态及本次是否按用户说明变更、待确认或未验证项。无改动如实说明，有冲突或未检查项不声称已完全对齐。仅更新状态或 `--check` 时仍遵守各自范围，不附带资产盘点或关联整理。整理完成不代表产品上线或用户验收，不自动提交、推送、合入或归档。
