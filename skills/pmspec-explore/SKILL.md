# PMSpec · Explore

把想法收敛为可立项的产品共识。输入是 `$ARGUMENTS` 和获准读取的相关资料，全程只读。

## 怎么问

1. 先描述用户、场景、问题和成功结果。能查明的事实先查，区分已上线事实、历史计划和待验证假设。
2. 按[就绪标准](references/readiness.md)复核主路径、范围、权限、状态和验收。每次问一个会改变决策的问题，优先问上游；用户补充信息后只复核受影响部分。高风险异常明确触发条件、系统处理和用户结果，后者包括反馈、能否继续、数据保留、重试与最终状态。
3. 存在实际取舍时比较可行方案及代价。用简图说明复杂路径，关键规则仍可直接核对。需要数据或原型才能判断时写明验证缺口；非阻塞假设标明影响后继续。

## 什么时候收敛

关键决策明确后，在对话中交付共识摘要，包括用户与问题、事实依据、选定方案、本次范围、验收结果及关键异常。仅列实际存在的假设和未决项。已有需求优先沿用真实名称，新需求推荐简短 kebab-case。

用户确认后给含实际需求名的下一步命令，例如 Claude Code 的 `/pmspec-propose simplify-checkout` 或 Codex 的 `$pmspec-propose simplify-checkout`。跨会话引用已确认摘要或原始批准来源。共识阶段只交对话摘要，下一步由用户选择。
